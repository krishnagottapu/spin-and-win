# Spin and Win — Business Requirements

## 1. Overview

Spin and Win is a lightweight event engagement application for live venues. Audience members interact via their personal phones with a communal TV display showing a prize wheel. The app delivers a gamified prize giveaway experience (drinks, merchandise, branded items) that drives attendee participation and creates memorable event moments.

The application is cloud-deployed (Vercel), requires no app installation, and works at any event with a TV and internet connection.

---

## 2. Target Users

| Role | Description |
|------|-------------|
| Event Attendees (Audience) | Scan QR code, register, spin the wheel, claim prizes |
| Event Staff | Verify winner identity and fulfill prizes to attendees |
| Event Admin | Configure events, manage prizes, generate staff codes, view reports |

---

## 3. Functional Requirements

### 3.1 Admin

- Admin logs in with username and password.
- Admin creates event sessions with the following configuration:
  - Event name
  - Start time and end time
  - Maximum spins per user (configurable, default 1)
  - Prize list: each prize has a name, probability weight, and inventory count
  - Optional "no prize" / "better luck next time" slice (toggle per event)
  - Wheel theme selection (corporate, party, holiday)
  - Sound preset selection (drumroll, game show, casino)
- Admin can edit active events (adjust prizes, extend time, change settings).
- Admin can manually end an event at any time (overrides configured end time).
- Admin generates one-time invite codes for staff to register their devices for that session.
- Admin has full access to all staff fulfillment features (scan, search, fulfill) without needing an invite code.
- Admin views live analytics during an event:
  - Current queue and active player
  - Prizes distributed vs. remaining inventory
  - Fulfillment rate
- Admin can export a detailed CSV report with fields:
  - Name, phone, prize won, fulfilled (yes/no), queue position, spin time, fulfillment time, staff member who fulfilled
- Admin can view and export reports for past events.

### 3.2 Audience (Mobile User)

- User scans QR code displayed on the TV to join the event.
- User registers with their name and phone number.
- User enters a queue if someone else is currently playing.
- User sees their queue position and estimated wait time on their phone.
- When it is their turn, user sees a large "TAP TO SPIN" button.
- User can only spin up to the configured maximum per session (default 1).
- After spinning, user's phone displays the result and a unique QR code for prize claiming.
- User can close and re-open the browser; re-entering their phone number recovers their session (shows queue position or result).
- Once a user has triggered their spin, they are done for that event.
- Users cannot join after the event end time, but users already in the queue play through (soft stop).

### 3.3 Staff

- Staff registers their device using a one-time invite code generated by the admin.
- Staff scans the result QR code from the user's phone to view the prize and fulfill it.
- Staff can also search winners by name or phone number (alternative to scanning).
- Staff sees the prize name and a "Mark Fulfilled" button.
- If already fulfilled, staff sees a red warning: "Already Claimed!" with who fulfilled it and when.
- Staff cannot fulfill the same prize twice (prevents double-claiming).

### 3.4 TV Display

- TV displays a large spin wheel and a QR code for joining the event.
- TV shows a scrolling leaderboard of all winners during idle periods.
- When a user is promoted to active: TV shows "[Name] is spinning..."
- When the spin is triggered: TV plays the configured sound preset, and the wheel animates.
- When the result lands: confetti animation, winning chime, and prominent display of winner name and prize.
- TV returns to idle state (QR code + leaderboard) after displaying the result for approximately 10 seconds.
- TV view supports fullscreen mode (hides browser URL bar for clean presentation).
- TV view is token-protected (only accessible with a valid, session-specific URL).

---

## 4. Concurrency and Queue Rules

- Only one user plays at a time.
- Other users are queued in first-in-first-out (FIFO) order.
- Queue position and estimated wait time are displayed on the user's phone.
- The next user is automatically promoted to active when the current player finishes.

---

## 5. Event Lifecycle

| State | Description |
|-------|-------------|
| Draft | Event created but not yet active. Users cannot join. |
| Active | Users can join and play. Normal operation. |
| Ending | End time reached. No new users can join, but the existing queue plays through (soft stop). |
| Ended | Admin manually stops the event OR the queue fully drains after soft stop. |

- Unfulfilled prizes remain claimable by staff after the event ends.
- Admin can force-end an event at any time, immediately clearing the queue and notifying waiting users.

---

## 6. Reporting Requirements

- Real-time dashboard visible to admin during the event.
- Post-event CSV/Excel export containing:
  - Participant name
  - Phone number
  - Prize won
  - Fulfilled status (yes/no)
  - Queue position at time of join
  - Spin timestamp
  - Fulfillment timestamp
  - Staff member who fulfilled the prize
- Historical access to past event reports (not just the current session).

---

## 7. Non-Functional Requirements

- Lightweight and fast-loading on mobile browsers.
- Deployed to Vercel (serverless architecture).
- Works on any modern mobile browser without app installation.
- Supports events with up to approximately 250 attendees.
- One active event at a time (multiple concurrent events is a future enhancement).
- Sound and visual effects optimized for engagement (must work through TV speakers).
- Accessible and usable in noisy event environments (large buttons, high contrast on TV).

---

## 8. Future Enhancements (Out of Scope for v1)

- Multiple concurrent events (different rooms/venues simultaneously).
- Custom audio file upload by admin per event.
- Custom logo and branding upload by admin per event.
- SMS notifications to queued users when their turn approaches.
- Analytics dashboard with historical trends across events.
